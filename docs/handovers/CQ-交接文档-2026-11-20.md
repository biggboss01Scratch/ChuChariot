## 接手复现

在仓库根目录运行以下命令。第一条预期返回 24 个实体、38 条事实和 38 条待审核事实。两条命令均可在没有本地原件的情况下运行。

```powershell
python -m chuchariot --dataset data/candidates/wheel-axle.v0.4.json --ontology data/ontology/ontology.v0.2.json validate --model-report data/scenes/model-inspection.json
python -X utf8 -m unittest discover -s tests -v
```

运行结果与 38 项测试覆盖见[进度记录](../progress.md)。检查页启动和停止方式见 [README](../../README.md)。原 PDF、图块与 GLB 节点图的查看方式见[融合检查](../fusion.md)。

需要原件或媒体时，按[来源登记](../sources.md)和[资料索引](../downloads.md)准备本地文件。

## 接力任务

**正式应用采用前后端分离。** 现有临时页面在 `frontend/inspector/`，通过 HTTP 调用 `chuchariot/preview.py`。正式前端放在 `frontend/`，正式 HTTP 服务将放在 `backend/`，并复用 `chuchariot/` 的知识查询能力。详见[设计要求](../software-plan.md#32-需求追踪)与[现有接口](../api.md)。

1. **下一棒可先做前端。** 先梳理「展品入口 → 部件浏览 → 部件详情」需要的实体、关系、证据与媒体，用 v0.4 候选数据设计页面。可参考 `GET /api/preview?review=1` 的响应做样例，保留待审核提示和缺资料的展示状态。
2. **后端对接。** 根据页面需求确定检索、详情、关系、证据和模型映射的接口字段。接口用稳定 ID 关联，并提供审核状态与媒体可用状态。正式响应和错误约定写入 [接口文档](../api.md)，供前端联调。
3. **知识补录。** 按[逐项核查](../source-coverage-audit.md)补齐关键部件和图证，核对 CH1：3、CH1：5、M1：201-1 的标本归属和现有组成关系，逐步形成正式审核记录。模型联动的现有问题见[模型核对](../fusion.md#模型核对)。
