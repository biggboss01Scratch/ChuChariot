只记录真实讨论和明确状态。建议不自动等同小组共识；改变范围时更新设计书需求表。

## D001：项目定位与重点

- 日期：2026-11-18。
- 状态：方向已由项目发起者明确；名称与展品范围待组内确认。
- 背景：最终需要一个可展示的知识系统，现有三维模型的正确性和完整性无法保证。
- 方向：知识图谱构建是重点，前端体现知识应用；三维与知识通过故事和讲解串联；AI 问答为加分项。
- 影响：知识与证据先行，模型不作为历史事实来源；模型精修优先服务于知识讲解。
- 待定：是否以九连墩六号车为唯一主展品，是否采用“专题交互导览系统”作为正式名称。

## D002：串行接力开发

- 日期：2026-11-18。
- 状态：开发方式已确认；具体流程为本文档集提出的实施约定。
- 决定：组员串行开发，每人维护文档后交给下一位，避免同时修改造成冲突；发起者先开展知识层构建。
- 影响：阶段完成须包括交接资料；下一位复现基线后再开发。
- 实施建议：单条共享开发线、一次一名修改者、按阶段提交、显式记录工作权；不需要部署额外协作系统。

## D003：分层与部署

- 日期：2026-11-18。
- 状态：本次计划采用的架构草案，供组内评审。
- 方案：资源层、知识与场景数据层、应用服务层、交互展示层，外加独立离线知识构建流程。
- 原因：明确知识、空间、导览内容和运行界面的职责，同时保持小型系统容易运行。
- 影响：逻辑分层不拆微服务；预设导览独立于 AI，前端执行三维动作，后端提供知识和配置。
- 替换条件：已有代码或课程要求证明该方案不适用时，记录实际理由再调整。

## D004：知识存储与数据契约

- 日期：2026-11-18。
- 状态：实施建议，P1/P2 前细化。
- 方案：先用版本化 JSON 建立可审核的数据基线，通过存储适配提供查询；优先采用独立事实记录统一追溯依据。
- 原因：先完成有来源的局部知识，避免数据库部署阻塞本体和数据核验。
- 影响：不宣称已接入 Neo4j；如接入数据库，确定唯一编辑入口和幂等导入策略。
- 待定：最终是否强制使用 Neo4j；具体字段和版本由 P1 数据规范固化。

## D006：知识层先落地可运行的标准库工具

- 日期：2026-11-19。
- 状态：已实施的首阶段技术选择。
- 方案：Python 3.11+ 标准库实现明确的数据约束、JSON/内存只读适配、CLI 查询和幂等导入；本轮验证 Python 3.12.4。知识代码放 `chuchariot/`，供后续后端直接复用。
- 原因：当前知识层无需 Web/AI/数据库依赖，下一位可先复现数据边界，避免环境部署阻塞内容整理。
- 影响：本体和验证器共同构成项目数据契约，不宣称通用 JSON Schema 或图数据库；未来扩展需同步版本和测试。
- 替换条件：P2 引入后端框架或 Neo4j 时仍保持事实与证据契约，记录兼容或迁移方式。

## D007：对照尺寸与未审核内容隔离

- 日期：2026-11-19。
- 状态：已实施的数据保护边界，候选内容待组员复核。
- 背景：资料汇编包含不同对照标本，现有模型不能证明它们属于主展品。
- 方案：增加 `ReferenceSpecimen`，本轮不把 CH1：3/CH1：5 尺寸归到主展品。9 条事实和 7 组类别映射全部为 `pending`；默认查询隐藏待审核事实及未确认尺寸。
- 影响：复核时显式使用审核视图；首批不是正式知识发布。GLB 映射绑定内容哈希和索引，不能只按重名节点绑定。
- 下一步：组员复核，追查原报告，明确哪些图示关系可一般化，再建立正式数据集。

## D008：先提供本地只读知识检查页

- 日期：2026-11-19。
- 状态：按用户请求已实施，属于 P1 辅助工具。
- 方案：标准库本地 HTTP 服务加普通 HTML/CSS/JavaScript，复用现有知识层；不引入前端框架、CDN 或正式后端框架。
- 原因：让组员通过搜索、图谱和证据页面检查现有数据，减少仅靠命令行理解知识结构的成本。
- 影响：页面默认显式候选模式并标记未审核；API 默认仍为已确认视图。只读，不写审核结果、不播放三维。正式 P2/P3 架构仍待对应阶段实现。
- 替换条件：正式前端/后端建立后可复用图谱与证据交互，或保留独立检查入口，不维护重复知识源。

## D009：本地Neo4j持久化与事实证据优先

- 日期：2026-11-23；状态：用户明确要求开始后已实施。
- 方案：单实例Neo4j Community、FastAPI、稳定业务ID、独立事实和证据、事务内重建关系、修订及审计；JSON转为导入／导出和历史发行资料。
- 发布：公众与内部路由分开鉴权，正式默认confirmed_only；课堂候选预览只由服务端配置，并保留推测性质和审核状态。
- 边界：当前为课程规模，复用全量一致快照查询，尚无大型图查询优化、在线本体编辑、多角色账号或公网部署。见[实际后端说明](backend.md)。
