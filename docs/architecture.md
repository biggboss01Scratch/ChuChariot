## 实际数据流

```text
人工整理的候选包 + 本体定义
        → 格式与语义约束校验
        → KnowledgeStore 只读内存快照
        → CLI 检索 / 详情 / 关系 / 证据 / 映射

候选包 → 完整校验 → 与目标按稳定 ID 合并 → 冲突拒绝 → 原子写入派生快照

资源目录 → 只读哈希登记与 GLB 解析 → 资源/模型结构报告
```

所有可追溯语义关系只维护在 `facts` 中，邻接视图由它投影。实体目录中的名称和备注用于整理，不能把其存在等同事实已审核。尺寸值存于尺寸记录，由 `HAS_MEASUREMENT` 事实关联证据和所有者；默认查询会隐藏尚未确认的尺寸值。

`KnowledgeStore` 从 JSON 重载快照，不执行累加写入；返回深拷贝，调用方不能修改内部数据。后续后端可直接调用其方法，再替换存储适配。当前只实现 JSON/内存适配，不能称为图数据库。

## 重构后的扩展边界

CLI 与检查服务分别使用知识查询模块。查询与导入共用校验模块，文件读写由 `dataset_io.py` 提供。预览仅在查询快照上附加 HTTP 展示信息与 PDF 可用性。后续新增字段时修改校验形状及数据规范，并检查对应消费者。

实体相关事实和映射通过内存索引查询。当前全量检查页仍为小数据集设计，每次加载会校验输入。正式 API 阶段可沿用查询行为并按需要增加分页和独立存储接口。

### 已具备的维护基础

- 知识数据、本体、资源报告与程序分开；新增符合契约的事实不需要修改页面或查询代码。
- 查询返回深拷贝，审核可见性有默认边界；导入幂等、冲突拒绝并原子替换文件。
- CLI、临时HTTP服务、页面、资源检查各有独立入口；知识层可在无Web服务、数据库或AI配置时运行和测试。
- 当前测试覆盖证据、尺寸归属、审核隔离、循环、导入冲突和HTTP读取/写入边界。混合审核状态下的快照与实体查询使用同一规则。

### 已识别的技术债与处理节点

| 位置 | 实际问题 | 后续处理与节点 |
|---|---|---|
| KnowledgeStore | 当前使用 JSON 加载与内存索引 | 在 P2 接入其他存储时按实际查询需求建立适配接口 |
| frontend/inspector/app.js | 状态、请求、列表、图谱、详情及事件集中；布局与部分显示文案绑定样例ID，中文关系字典也有重复 | 保持临时检查页范围；扩成正式前端前拆分请求、状态、图谱和面板，布局/示例文案转展示配置，区分本体语义与UI短标签 |
| preview.py与resources.py | 默认模型报告路径、res:005资源标识绑定当前样例 | 支持多个数据集/模型前改为显式场景配置或资源元数据选择，并校验报告对应模型版本 |

### 后续模块边界

- 校验负责数据约束；存储负责读取/持久化；查询服务统一处理审核过滤、关系、证据和映射。HTTP路由负责参数、调用和响应。
- 三维模块消费实体ID、模型映射与场景配置；不读取PDF、不自行裁定事实审核状态。图谱视图与三维共享选择状态。
- AI适配模块消费查询结果和证据，调用失败可独立处理；不修改正式知识。离线抽取继续独立于网站请求。
- 拆分时保留已有可用入口，先通过既有行为测试，再开展新功能；新增模块须有独立职责或明确替换需求。当前无需为了凑层次创建空目录和多套框架。

## 临时检查服务

`python -m chuchariot preview` 绑定 `127.0.0.1`，以标准库 `ThreadingHTTPServer` 提供检查页。静态文件仅允许 index.html、style.css、app.js；原文只按已登记来源 ID 提供，POST 不支持写入。

`/api/preview` 默认输出已确认视图；`?review=1` 才返回候选。尺寸实体通过 `KnowledgeStore` 输出，保持未审核尺寸隔离。每次请求重新读取并校验 JSON，文件变更后点击重新加载即可，不缓存另一套知识。前端的默认候选视图通过显式参数请求，并持续展示审核提示。

窗口中没有外部字体、JS 库或 CDN 请求；普通检查可断网进行。原文 PDF 是本机文件，是否可用由显式资源目录决定。

资源盘点不证明模型几何正确；页码/引用格式校验不证明引文真实或推导成立。知识和内容审核仍需独立进行。
